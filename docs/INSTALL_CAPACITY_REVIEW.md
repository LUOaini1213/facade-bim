# Installation capacity and read-only delivery verification

The previous `install_plan` accepted a 3 h U4 panel with only 1 crew-hour of
daily capacity, assigned it to the following day, and still exceeded that
day's capacity. Explicit zero crews also silently selected the default crews.
The four matching public-function controls fail against the original schedule
from [the baseline delivery](https://github.com/LUOaini1213/facade-bim/tree/cfb269554d29647b2b132bb0eef187711cd88648)
with assertion failures, not import/setup errors.

Only `None` selects default values. Crew counts are positive integers; crew
hours and panel durations are finite positive numbers. A whole panel must fit
within a day's aggregate crew-hours. Otherwise the function raises `ValueError`
without pretending another day can make the same insufficient capacity valid.
This preserves the existing aggregate-hours, non-preemptive scheduling model;
it does not add individual crew ownership, holidays or split tasks.

Regression controls cover invalid explicit/configured values, finite-product
overflow, invalid panel durations, exact-capacity and fractional tasks, sequential
whole-task rollover, Sunday skipping, and unchanged defaults. The defaults and
published quantities/schedule must still exactly match all committed `data/`
files and the IFC export from the committed native model.

## Existing artifacts, current verification

No committed model, image, original quality/replay report, CSV or IFC is replaced
in this change. A fresh IFC is exported only into a temporary directory for
comparison. `delivery.py --revalidate` is an explicit, complete **read-only**
verification mode. It rejects changed original artifacts before running any
check; then runs all nine existing data, IFC, test, IDS, quality, replay, profile
and README checks. A failed/interrupted run cannot write a success receipt.
Inputs, artifacts and the index are compared again before an atomic index write.

The original index `inputs`, artifact identities, build environment and build
times remain intact. Its appended `read_only_verification` binds the current
sources (including this explanation) to the unchanged artifacts, exact commands
and actual verification environment. `source_base_commit` is the working tree's
Git base; the input hashes identify the actual sources, including uncommitted
changes present at verification. It is **not** a claim that the old artifacts
were originally generated by those sources. `native_execution=false` explicitly
records that Rhino modelling/rendering did not run.
The original index body is checked against that fixed Git commit's index blob
before revalidation and during later checks. Rewriting an old build environment
or artifact hash and recalculating a local digest cannot bless a new historical
identity. CI fetches the original history for this check; a source archive without
the fixed Git history cannot verify this receipt.
The first `baseline_commit` is retained on subsequent revalidations, even if the
current source HEAD changes; `source_base_commit` records the current code base
separately. An existing receipt cannot be re-anchored to a later edited baseline.

All CLI index writers use the same OS lock, including native rebuild and direct
index writes. The OS releases it after process exit/crash; the small lock file is
retained to keep one shared inode. Writers parse a single index byte snapshot and
use a unique atomic temporary file. Concurrent cooperating CLI writers fail
before checks/writes. This does not block arbitrary editors that ignore the lock,
nor make arbitrary malicious Git-history rewrites trustworthy; snapshot checks
still detect external edits during the verification interval.

The standard `--check` validates the current input snapshot, the retained original
build identity and every artifact fingerprint before and after its full checks.
CI uses the same fingerprints after independent required checks, without writing
replacement IDS/quality reports. Regressions reject edited native bytes, changed
inputs during checks, stale verified inputs, incomplete commands/fingerprints,
tampered original build identity and a concurrent index edit. A real native
rebuild remains necessary when any formal artifact needs to change.

The local results and unchanged-artifact identities are recorded separately in
[the validation receipt](install_capacity_review.json), rather than changing
the project's historical figures. This fictional demonstration is not an
approved fabrication plan or a project-specific resource schedule.
